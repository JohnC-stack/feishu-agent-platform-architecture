# P6 管理中心操作说明书

## 1. 登录入口

管理中心只允许飞书企业身份登录，不提供平台密码、本机会话或手工 Open ID 登录。

- 普通成员入口：`http://127.0.0.1:5173/#overview`
- 超级管理员入口：`http://127.0.0.1:5173/#super-admin-login`
- OAuth 回调：`http://127.0.0.1:5173/v1/admin/auth/feishu/callback`

普通入口允许已经绑定任一平台角色的飞书用户登录，并只显示其角色允许的菜单和数据。超级管理员入口不会自动授权，只允许已经绑定 `administrator` 的飞书用户进入。登录成功后平台签发 HttpOnly 会话；退出、会话到期或 Control API 重启后需要重新登录。

## 2. 角色和可操作范围

| 角色       | 默认可见页面                                        | 主要能力                                              |
| ---------- | --------------------------------------------------- | ----------------------------------------------------- |
| 只读成员   | 驾驶舱、任务、运行、执行器、集成、说明书            | 查看运行状态和业务任务，不执行管理写操作              |
| 运行操作员 | 驾驶舱、任务、运行、执行器、集成、Trace、告警、运维 | 确认告警，申请受治理运维操作                          |
| 审批员     | 驾驶舱、审批中心、说明书                            | 查看审批；审批决策继续通过飞书审批卡完成              |
| 审计员     | 驾驶舱、日志与 Trace、说明书                        | 查看任务链路和脱敏审计，不修改平台状态                |
| 超级管理员 | 全部 14 个页面                                      | 管理角色、告警、运维、配置/发布视图和所有治理读取能力 |

角色能力由服务端计算。隐藏菜单不是权限边界；快照和 Trace 也会在服务端执行授权和数据过滤。多个角色同时绑定时按权限并集合并。

## 3. 超级管理员首次配置

至少保留一名通过启动配置绑定的超级管理员：

```dotenv
GOVERNANCE_ADMIN_USER_IDS=ou_xxx
```

启动配置生成的绑定在页面标记为“启动配置”，不能从管理中心删除。这样可以避免误操作导致所有管理员被锁在系统外。配置发生变化后按发布流程重启 Control API 并重新登录。

超级管理员不得删除自己当前使用的 `administrator` 角色。如果需要交接：

1. 先为接任人的飞书 Open ID 新增“超级管理员”角色；
2. 让接任人通过超级管理员入口登录并确认可访问“用户与权限”；
3. 由接任人移除前任在管理中心创建的管理员绑定；
4. 若前任属于启动配置，再通过受控配置发布修改环境配置并重启验证。

## 4. 用户与权限管理

进入 **安全治理 → 用户与权限**。

### 新增角色

1. 选择主体类型：用户或群组；
2. 输入飞书用户 Open ID（`ou_...`）或群组 ID（`oc_...`）；
3. 选择角色；
4. 点击“保存角色绑定”；
5. 页面刷新后确认绑定出现在表格，来源显示“管理中心”；
6. 让目标用户退出后重新通过普通入口登录，确认菜单和功能符合角色范围。

### 移除角色

1. 在绑定表找到目标主体、角色和来源；
2. 确认不是“启动配置”，也不是当前登录人的超级管理员角色；
3. 点击“移除”；
4. 确认绑定消失，并在日志与 Trace/审计记录中检查 `access.manage` 结果。

每次新增和移除都会立即刷新服务端策略并写入审计。角色变更不修改飞书组织权限，也不授予飞书文档或多维表格权限。

## 5. 日常运行检查

每天先进入 **管理驾驶舱**，按以下顺序检查：

1. Hero 状态是否为稳定，三项服务是否在线；
2. 开放告警和严重告警是否新增；
3. 队列 waiting/active/delayed 是否持续增长；
4. 失败任务是否增加，点击任务进入 Trace 定位；
5. 待审批数量是否异常积压；
6. Token/成本预算是否达到 80% 或超过上限。

点击驾驶舱的快捷管理卡可直接进入用户权限、告警、运维或配置页面；未授权角色不会看到对应入口。

## 6. Trace 和故障定位

1. 从任务表选择失败任务并进入 **日志与 Trace**；
2. 核对来源事件、任务、BullMQ attempt、执行器 run、工具事件和错误码；
3. 使用 correlation ID 关联审计事件；
4. 先判断是授权、资源白名单、依赖离线、限流、超时还是执行器失败；
5. 对未消除的根因不要直接重试；处理根因后再提交运维申请。

页面及 API 对潜在凭据递归脱敏。不要将 Secret、Cookie、访问令牌或完整连接串粘贴进目标 ID、确认文本或工单。

## 7. 告警处理

运行操作员或超级管理员进入 **平台运维 → 告警中心**：

1. 按严重度和状态确定处理顺序；
2. 跳转到关联任务或服务进行定位；
3. 记录根因和处理动作；
4. 点击确认告警，平台写入操作人和审计；
5. 告警确认不等于故障恢复。故障仍存在时快照会继续更新 `last_seen_at`，条件消失后才转为已恢复。

## 8. 运维操作

进入 **平台运维 → 运维操作**，选择取消、重试、清理、重启或回滚，填写目标类型和目标 ID。确认文本必须完全等于页面给出的 `确认<中文操作>:<目标 ID>`。

| 操作 | 风险 | 提交后的行为                       |
| ---- | ---- | ---------------------------------- |
| 取消 | 中   | 授权和精确确认通过后调用任务协调器 |
| 重试 | 高   | 创建待审批申请，不立即执行         |
| 清理 | 高   | 创建待审批申请，不立即删除资源     |
| 重启 | 严重 | 创建待审批申请，不立即重启服务     |
| 回滚 | 严重 | 创建待审批申请，不立即改变版本     |

高风险操作由 P5 审批状态机控制；P6 只登记和展示状态。部署层实际执行器属于后续阶段，不能把“已批准”误认为“基础设施已完成变更”。

## 9. 发布、备份与配置

- **配置中心**只显示键名、是否已配置、来源和是否需要重启，不显示配置值。
- **发布与备份**展示版本、校验和、备份校验、恢复演练和配置版本记录。
- 回滚必须从运维操作提交并进入审批，不能在浏览器直接执行。
- 生产环境管理台只在公司内网/VPN 通过 HTTPS 提供；不得开放公网入站。

## 10. 常见问题

### 飞书登录后提示无权限

让超级管理员核对该用户的应用内 Open ID 是否已绑定角色。不同飞书应用下的 Open ID 可能不同，不能直接复用另一应用的值。

### 超级管理员入口提示需要超级管理员角色

说明当前飞书用户没有 `administrator` 绑定。该入口不负责提权；由现有超级管理员新增绑定，或通过受控启动配置恢复管理员。

### 菜单比其他用户少

这是角色隔离的预期行为。查看右上角角色标识和本页角色矩阵；如确需扩权，由超级管理员新增最小必要角色。

### 修改角色后页面没有变化

目标用户退出平台会话后重新飞书登录，再刷新页面。若仍未更新，检查 Control API、PostgreSQL 和审计事件。

### 页面显示旧数据或服务异常

先手工刷新；仍失败时检查 Control API 3000、Feishu Gateway 3100、Windows Worker 3200 的 readiness，再检查 PostgreSQL、Redis 和 BullMQ。
